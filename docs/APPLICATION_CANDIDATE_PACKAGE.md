# Application candidate package

CI now builds a no-dev PHP 8.3 runtime candidate only after PHPUnit/build/route checks, clean MySQL 8 migrations, and synthetic legacy MariaDB upgrade checks pass. A separate clean checkout installs production dependencies from composer.lock without dev packages, scripts or plugins; verifies platform requirements, discovers providers and compiles routes/views, then builds Vite assets. It packages tracked runtime source, vendor and public/build. No composer update runs.

The artifact jwtc-application-candidate contains a commit-named tar.gz, SHA256SUMS and release-manifest.json with per-file SHA-256. It is retained for seven days. The manifest explicitly reports production_ready=false. CI packaging is not a security-advisory audit, actual hosted browser test, backup/restore, full asset reconciliation or release authorization.

Excluded: .env and environment variants, all runtime storage, compiled runtime config/cache, tests, source-control metadata, known public upload/private document directories, all public/images (mixed legacy static images and user photos), SQL/SQLite/ZIP/key/PEM/log/backup files. Symlinked runtime files are refused. Real live applicant data never enters GitHub CI. Legacy branding/images and all upload roots MUST be separately reconciled from a retained current backup before staging cutover; the package alone is not a complete historical website copy.

Do not unpack this archive over the live root. Verify package and file hashes, then use a new private isolated staging root/database with securely supplied original APP_KEY and staging-specific credentials. Retain production .env, public/private uploads, all current records, SEO and analytics. Complete docs/STAGING_INTEGRATION_PRECHECK.md and the module gates first. Never use migrate:fresh/refresh/reset/db:wipe or destructive down() as deployment/rollback.

Outstanding operational inputs: verified consistent CURRENT live database and file backups with off-host copy, original APP_KEY escrow, independent restored staging database/root, live asset/document-root/symlink inventory, real SMTP/hCaptcha/PDF tests, permissions and acceptance results, a rehearsed write-cutover/rollback strategy. SSH preflight only proved connection/PHP/tools/permissions; it did not establish these facts. Full business feature coverage, frontend accessibility/performance, dependency advisory review and legacy API compatibility still need acceptance. No production upload or migration is triggered by this job.
